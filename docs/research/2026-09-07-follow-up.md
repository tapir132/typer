# Typer: the next improvements that can be measured

September 7, 2026. Audience: Typer's developer and users evaluating its typing behavior. Scope: additions beyond paired timing, rollover, empirical profiles and held-out comparison. Existing profile data must stay readable; final text must remain exact; no external writing is captured for this work.

The most useful immediate additions are a real local delivery check and a clearer, more honest comparison report. Keyboard/layout-specific profiles and learned pause contexts are the next model improvements to evaluate. More independent jitter would not resolve the current evidence gaps.

## Evidence and decisions

**Measure delivery independently from the plan.** Killourhy and Maxion's [2008 clock-resolution experiment](https://www.cs.cmu.edu/~ksk/KillourhyMaxion2008b.pdf) shows that clock resolution can change measured keystroke features and downstream evaluation. Their [2010 controlled keypad experiment](https://www.cs.cmu.edu/~ksk/MaxionKillourhy2010.pdf), particularly its apparatus and calibration sections, separates human behavior from keyboard and system effects. These are controlled biometric studies, not validation of Typer's generator. They support careful instrumentation, not a numerical realism target.

Typer now sends three fixed scenarios through its production scheduler and event factory into a dedicated AppKit receiver. The target is Typer's process, using Apple's [process-addressed event API](https://developer.apple.com/documentation/coregraphics/cgevent/posttopid(_:)). Events are tagged with [64-bit event source data](https://developer.apple.com/documentation/coregraphics/cgeventfield/eventsourceuserdata). An application-lifetime local router consumes tagged events even after cancellation, so late keys do not enter another Typer text field.

The receiver records both Apple's [event timestamp](https://developer.apple.com/documentation/appkit/nsevent/timestamp), which describes occurrence time, and the handler's monotonic arrival time. Comparing both prevents accurate timestamps from concealing a stalled event queue. The check covers text, missing/duplicate events, ordering, modifiers, overlap, and median/p95 absolute timing error. A text/event integrity pass is explicitly separate from timing quality. The 750 ms final drain and nearest-rank percentile are engineering choices, not research thresholds. This route does not measure physical keyboard latency or certify another editor or the global HID path.

**Compare like trials and show variability.** The clock study controlled the input text and other potential confounders; the same principle motivates keeping task contexts and passages explicit here. Typer's validation can now select any retained training context. It never mixes Copy, Sprint, Freewrite and Live. Its overview pairs the same human session, training sessions, seed and target WPM, then reports median W1 and minimum–maximum ranges. Missing evidence remains a dash. Several seeds share the same two human sessions, so no extra independent human evidence is claimed.

A code audit found a concrete validity issue: Copy/Sprint could be labeled matched simply because a reference prompt existed, even though saving was allowed before the passage was complete. New samples record whether the final editor text exactly equals that prompt. Partial and older unverified samples remain usable, with an explicit limitation. This optional field does not turn current samples into Legacy profiles. Another audit fix prevents invalid or very long timing gaps from joining separate bursts.

**Separate keyboard and language contexts next.** Wahab and colleagues' [2022 multi-keyboard and bilingual study](https://par.nsf.gov/servlets/purl/10333157) collected data across four keyboard types and English/Chinese tasks, and evaluated cross-context effects. Its authentication results do not specify how much any one Typer profile will change, but they argue against silently treating all hardware and layouts as interchangeable. The sensible next addition is a user-visible keyboard/layout context for each sample and profile, with explicit switching and migration. Typer currently assumes US QWERTY physical key mapping; displaying the active input source in the delivery report is diagnostic information, not layout adaptation. Do not infer the actual finger used from key codes.

**Learn pauses by context after collecting more evidence.** Chukharev-Hudilainen's [2014 spontaneous-writing study](https://www.jowr.org/jowr/article/view/682) modeled inter-key distributions in chat and proposed task-specific pause thresholds. Together with the previously reviewed [2016 punctuation-boundary study](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2016.01678/full), it supports investigating word, punctuation and task context. It does not justify treating 500 ms, 1 s, or 2 s as a universal boundary for thinking. A useful follow-up would retain bounded pause summaries by boundary and task, then compare a contextual generator with the existing generator on untouched sessions. Those observations are not yet available, so no new tuned pause model is claimed in this pass.

## Priorities after this pass

1. **Keyboard/layout profiles and layout-aware output.** Preserve explicit contexts and stop treating non-US layouts as if they used the same physical map. Test dead keys, composition methods and Unicode before promising general support.
2. **Conditional pause and repair models.** Collect sufficient examples at word, sentence and repair boundaries; use measured rates and cadence with sparse-data fallback. Compare against the current model before changing defaults.
3. **Dedicated external receiver and editor compatibility checks.** Extend measurement to the normal HID route with a controlled target application, then verify final text and delivered timings in representative editors. Autocorrect, rich-text commands and IMEs remain application-dependent.
4. **Fresh-session calibration.** Collect six to eight same-context human sessions across separate sittings. Keep at least two later sessions untouched. Freeze settings, compare all paired seeds and the human reference, and collect new sessions after tuning. The sample counts are a practical protocol, not a scientific sufficiency guarantee.

## Research limits and verification

Discovery covered clock/latency measurement, cross-device and language effects, and pause/burst models. Follow-up retrieved author-hosted CMU papers, the original keyboard study via NSF, the journal pause study, and Apple API documentation. The NSF PDF open endpoint was intermittently unavailable; the primary manuscript was accessible through indexed full text. No third-party dataset, learned artifact, participant identity or captured human document is bundled.

Search stopped when these implementation choices had direct evidence or a stated engineering limitation. Additional literature cannot replace fresh human recordings or an external receiver experiment. The changes add measurement capability and correct specific validity errors; they do not establish improved population-level realism.

Deterministic tests cover ideal receipts, missing/extra events, ordering, flags, nonfinite clocks, Unicode text equality, cancellation status, receiver stalls with unchanged event timestamps, context selection, temporal holdout separation, paired summaries, completion metadata compatibility and burst boundaries. The graphical check is reproducible with `scripts/verify-playback.sh`, which runs only the production playback components in a temporary app using Typer's normal signing identity and existing Accessibility grant. It does not edit permissions or load saved profiles. The detailed protocol and output definitions are in [VALIDATION.md](../VALIDATION.md).

Final local verification passed 56 automated tests with warnings treated as errors. The native AppKit harness passed all three scenarios: 52/52 rhythm events, 74/74 correction events and 54/54 punctuation/Unicode events, with exact final text and no missing, duplicate, ordering or modifier errors. Planned and received rollover both measured 56% for the overlap fixture. Across scenarios, median arrival-vs-schedule absolute error was 4.95–5.65 ms and p95 was 8.72–9.95 ms. These are descriptive observations from one final run on one Mac with the U.S. input source, not latency guarantees or human-realism scores. The automated receiver ran in the background; the user-facing focus-stop policy remains separate. Native screenshots of readiness, validation overview and delivery results were inspected.
